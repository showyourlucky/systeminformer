# System Informer 汉化规则分析与源码回写需求说明

## 一、需求背景

当前项目为 **System Informer**，属于 Windows 平台 C 语言 / Win32 桌面应用项目。项目中存在大量用户可见英文文本，这些文本可能分布在：

* C 源码文件
* C 头文件
* Windows 资源文件
* 插件资源文件
* 菜单资源
* 对话框资源
* 字符串表资源
* 控件 Caption
* MessageBox / TaskDialog / Tooltip / StatusBar / Tray 提示
* 属性页、设置页、上下文菜单、列名、错误提示等 UI 场景

本需求的目标是对 System Informer 项目源码中的字符串进行逐个文件分析，判断其是否属于需要汉化的内容，并为每一类内容生成可复用的提取规则或排除规则。

最终需要形成一套可执行闭环：

```text
Codex 逐文件分析源码
  ↓
沉淀待汉化规则和排除规则
  ↓
记录字符串与规则的对应关系
  ↓
Python 导出未翻译文件
  ↓
人工翻译
  ↓
Python 校验并回写源码
  ↓
生成汉化后的 System Informer 源码
```

---

## 二、核心目标

本项目的核心目标不是简单提取源码中的字符串，而是建立一套面向 System Informer 的汉化分析、规则沉淀和源码回写流程。

需要完成以下目标：

1. 由 Codex 对 System Informer 项目文件逐个进行分析。
2. 识别源码中出现的字符串内容。
3. 结合字符串上下文判断其是否属于需要汉化的用户可见文案。
4. 对需要汉化的内容提取对应的正则规则。
5. 对不需要汉化的内容提取对应的排除规则。
6. 建立字符串、源码位置、上下文、规则、状态、判断原因之间的对应关系。
7. 记录每个文件的分析进度。
8. 页面展示分析结果、规则、进度和待复核内容。
9. Python 根据 Codex 的分析结果导出未翻译文件。
10. 人工在未翻译文件中填写中文译文。
11. Python 读取已翻译文件，将译文应用回 System Informer 源码。
12. 最终形成稳定、可重复执行的汉化流程。

---

## 三、执行分工

本项目分为四类角色：

| 角色        | 负责内容                                            |
| --------- | ----------------------------------------------- |
| Codex     | 逐个文件分析源码，判断字符串是否需要汉化，提取待汉化规则和排除规则，维护字符串与规则的对应关系 |
| Python 脚本 | 根据 Codex 已确认的分析结果导出翻译文件，并将人工翻译结果回写到源码           |
| 人工翻译      | 手动填写中文译文，确认待复核内容                                |
| 页面        | 展示分析结果、规则、进度和待复核内容，辅助人工确认                       |

需要明确：

```text
Codex 是主要分析者。
Python 不是主要分析工具。
Python 不负责复杂源码语义判断。
Python 只负责导出、校验、拆分和回写。
```

---

## 四、System Informer 项目特点

System Informer 与普通 Web 项目不同，汉化分析需要重点考虑以下特点：

1. 项目主要使用 C 语言开发。
2. 大量 UI 文案可能不在 `.c` 文件中，而是在 `.rc` 资源文件中。
3. 存在 Win32 API 调用场景，例如 `MessageBox`、`TaskDialog`、`SetWindowText`、`InsertMenuItem` 等。
4. 存在 ANSI 字符串、宽字符字符串和 `TEXT()` / `_T()` 宏。
5. 存在大量资源 ID，例如 `IDS_XXX`、`IDC_XXX`、`IDD_XXX`、`IDM_XXX`。
6. 插件目录中也可能包含独立 UI 和资源文件。
7. 部分字符串属于系统内部标识、注册表路径、对象名称、内核对象名、NT 路径、权限名、服务名、性能计数器、命令行参数，不应汉化。
8. 汉化时需要保留快捷键助记符、格式化占位符、换行、制表符、资源 ID 和上下文逻辑。

## 五、分析文件范围

需要重点扫描以下文件类型：

```text
.c
.h
.rc
.rc2
.mc
.manifest
.xml
.json
.ini
.txt
```

其中优先级最高的是：

```text
.rc

```

原因：

* `.rc` 文件通常包含菜单、对话框、字符串表、版本信息等主要 UI 文案。
* `.c` 文件中可能包含运行时动态生成的提示、错误、菜单、列名和日志。
* `.h` 文件中可能包含宏定义、资源 ID、字符串常量。

## 七、字符串识别类型

系统需要识别以下字符串形式。

### 1. 普通 C 字符串

```c
"Properties"
"Unable to open process."
```

### 2. 宽字符字符串

```c
L"Properties"
L"Unable to open process."
```

### 3. TEXT / _T 宏字符串

```c
TEXT("Properties")
_T("Properties")
```

### 4. 多段拼接字符串

```c
"Unable to open "
"the selected process."
```

### 5. 格式化字符串

```c
"Unable to open process %lu."
"%s (%lu)"
```

### 6. 资源文件字符串

```rc
CAPTION "System Informer"
LTEXT "Process:", IDC_STATIC, 7, 7, 50, 8
PUSHBUTTON "OK", IDOK, 10, 10, 50, 14
MENUITEM "Properties", IDM_PROPERTIES
```

### 7. STRINGTABLE 字符串

```rc
STRINGTABLE
BEGIN
    IDS_PROCESS_PROPERTIES "Process Properties"
    IDS_UNABLE_TO_OPEN_PROCESS "Unable to open process."
END
```

### 8. VERSIONINFO 字符串

```rc
VALUE "FileDescription", "System Informer"
VALUE "CompanyName", "Winsider Seminars & Solutions, Inc."
```

版本信息中的部分字段需要特殊处理，不一定全部汉化。

## 八、需要汉化的内容判断标准

以下内容通常属于待汉化内容。

### 1. 菜单文本

```rc
MENUITEM "Properties", IDM_PROPERTIES
MENUITEM "Terminate", IDM_TERMINATE
```

### 2. 对话框标题

```rc
CAPTION "Process Properties"
```

### 3. 控件文本

```rc
LTEXT "Command line:", IDC_STATIC, 7, 7, 60, 8
PUSHBUTTON "Cancel", IDCANCEL, 10, 10, 50, 14
```

### 4. 字符串表文案

```rc
IDS_CONFIRM_TERMINATE "Are you sure you want to terminate the selected process?"
```

### 5. MessageBox / TaskDialog 文案

```c
MessageBox(hwnd, L"Unable to open process.", L"System Informer", MB_ICONERROR);
```

### 6. 状态栏、托盘、Tooltip 文案

```c
PhSetStatusText(L"Ready");
```

### 7. 列名、Tab 名、属性页名称

```c
PhAddTreeNewColumn(tree, PH_TREENEW_COLUMN_NAME, L"Process", ...);
```

### 8. 用户可见错误提示

```c
L"Unable to query process information."
```

### 9. 设置项、选项说明、确认提示

```c
L"Enable kernel-mode driver"
L"Show processes from all users"
```

---

## 九、不需要汉化的内容判断标准

以下内容通常不应汉化，需要生成排除规则。

### 1. 资源 ID、控件 ID、菜单 ID

```c
IDS_PROCESS_PROPERTIES
IDC_PROCESS_LIST
IDM_TERMINATE
```

### 2. 注册表路径

```c
L"Software\\Microsoft\\Windows\\CurrentVersion\\Run"
```

### 3. NT 对象路径

```c
L"\\Device\\HarddiskVolume1"
L"\\BaseNamedObjects\\"
```

### 4. 文件路径、DLL 名、EXE 名

```c
L"SystemInformer.exe"
L"ntdll.dll"
L"\\SystemRoot\\System32\\drivers\\"
```

### 5. 命令行参数

```c
L"-install"
L"-uninstall"
L"-silent"
```

### 6. 服务名、驱动名、对象名

```c
L"KSystemInformer"
L"SystemInformer"
```

这类内容是否汉化需要结合上下文判断。

如果是用户可见显示名称，可以进入待复核。

如果是服务内部名称、驱动内部名称、对象名，则不应汉化。

### 7. 格式标识、协议名、权限名

```c
L"SeDebugPrivilege"
L"NT AUTHORITY\\SYSTEM"
L"Global\\"
```

### 8. 颜色、样式、类名、窗口类名

```c
L"SysListView32"
L"Button"
L"Static"
```

### 9. 纯格式化占位符

```c
L"%lu"
L"%s"
L"0x%Ix"
```

包含占位符的完整用户提示可以汉化，但占位符本身必须保留。

### 10. 调试日志、开发者内部标记

```c
L"debug"
L"trace"
L"assert"
```

如果日志会展示给最终用户，则需要复核。

## 十、Codex 负责的工作

Codex 是本项目中负责源码理解和规则判断的核心角色。

### 1. 逐个文件分析

Codex 需要按文件逐个分析 System Informer 项目源码，重点分析：

```text
.rc
.rc2
.c
.h
```

分析时需要关注：

```text
字符串本身
字符串所在上下文源码
字符串所在文件路径
字符串所在行号
字符串所属资源或函数
字符串是否用户可见
字符串是否应被汉化
字符串是否应被排除
```

---

### 2. 判断字符串状态

Codex 需要结合上下文判断字符串属于以下哪一类：

```text
待汉化
排除
待复核
```

判断依据包括：

```text
是否来自菜单、对话框、按钮、控件、字符串表
是否传入 MessageBox、TaskDialog、SetWindowText 等 UI API
是否属于路径、注册表、DLL 文件名、命令行参数、资源 ID
是否属于服务名、驱动名、内部对象名
是否包含格式化占位符
是否包含菜单助记键
是否可能展示给用户
```

---

### 3. 提取待汉化规则

对于确认需要汉化的内容，Codex 需要提取对应的正则规则。

要求：

```text
每条待汉化内容都要能找到对应的提取规则
规则不能太宽
规则需要结合上下文
规则需要记录命中的字符串
规则需要记录适用文件类型
规则需要记录规则说明
```

示例：

```regex
^\s*MENUITEM\s+"([^"]+)"\s*,
```

说明：

```text
用于提取 RC 资源文件中的菜单项文本。
```

---

### 4. 提取排除规则

对于确认不需要汉化的内容，Codex 需要提取对应的排除规则。

要求：

```text
每条排除内容都要能找到对应的排除规则
排除规则不能误伤用户可见文案
排除规则需要记录排除原因
排除规则需要记录命中的字符串
```

示例：

```regex
\b[A-Za-z0-9_.-]+\.(?:dll|exe|sys|mui|pdb|lib)\b
```

说明：

```text
用于排除 DLL、EXE、SYS 等文件名。
```

---

### 5. 维护对应关系

Codex 分析后，需要维护以下对应关系：

```text
字符串 → 文件路径
字符串 → 行号
字符串 → 上下文源码
字符串 → 待汉化规则
字符串 → 排除规则
字符串 → 判断状态
字符串 → 判断原因
```

每个字符串最终必须属于以下结果之一：

```text
待汉化规则覆盖
排除规则覆盖
待复核
```

不能出现无状态、无原因、无规则的字符串。

## 十一、C 源码待汉化规则示例

### 规则 1：MessageBox 文案

```regex
\bMessageBox(?:W|A)?\s*\(\s*[^,]+,\s*(L|TEXT|_T)?\(?\s*"([^"]+)"\s*\)?\s*,\s*(L|TEXT|_T)?\(?\s*"([^"]+)"\s*\)?
```

用途：

* 提取 MessageBox 的正文和标题。
* 正文通常需要汉化。
* 标题如果是产品名 `System Informer`，可不汉化或单独复核。

---

### 规则 2：TaskDialog 文案

```regex
\bTaskDialog(?:Indirect)?\s*\(
```

用途：

* 定位 TaskDialog 调用。
* TaskDialog 通常使用结构体字段传入标题、正文、按钮文本。
* 需要结合上下文提取 `pszWindowTitle`、`pszMainInstruction`、`pszContent`、`pszVerificationText` 等字段。

说明：

TaskDialog 场景不建议只靠单条正则直接提取，应结合上下文窗口分析。

---

### 规则 3：宽字符串用户提示

```regex
\bL"([^"\\]*(?:\\.[^"\\]*)*)"
```

用途：

* 初步提取 C 宽字符串。
* 该规则只能作为基础提取规则，不能直接判断是否汉化。
* 后续必须结合上下文判断。

---

### 规则 4：TEXT / _T 宏字符串

```regex
\b(?:TEXT|_T)\s*\(\s*"([^"\\]*(?:\\.[^"\\]*)*)"\s*\)
```

用途：

* 提取 Win32 兼容宏中的字符串。
* 需要结合调用函数、变量名、赋值目标判断是否汉化。

---

### 规则 5：SetWindowText 类 UI 文案

```regex
\bSetWindowText(?:W|A)?\s*\(\s*[^,]+,\s*(?:L|TEXT|_T)?\(?\s*"([^"\\]*(?:\\.[^"\\]*)*)"\s*\)?\s*\)
```

用途：

* 提取窗口标题、控件文本等运行时设置的 UI 文案。
* 通常属于待汉化内容。

---

## 十二、RC 资源文件待汉化规则示例

### 规则 1：CAPTION

```regex
^\s*CAPTION\s+"([^"]+)"
```

用途：

* 提取对话框标题。
* 通常属于待汉化内容。

---

### 规则 2：控件文本

```regex
^\s*(?:LTEXT|CTEXT|RTEXT|PUSHBUTTON|DEFPUSHBUTTON|CHECKBOX|RADIOBUTTON|GROUPBOX)\s+"([^"]+)"\s*,
```

用途：

* 提取资源文件中的控件显示文本。
* 通常属于待汉化内容。

---

### 规则 3：菜单项

```regex
^\s*MENUITEM\s+"([^"]+)"\s*,
```

用途：

* 提取菜单显示文本。
* 通常属于待汉化内容。

注意：

菜单中的 `&` 是 Windows 助记键标识，例如：

```text
&File
E&xit
```

汉化时需要保留或重新规划助记键，例如：

```text
文件(&F)
退出(&X)
```

---

### 规则 4：POPUP 菜单

```regex
^\s*POPUP\s+"([^"]+)"
```

用途：

* 提取资源文件中的菜单分组标题。
* 通常属于待汉化内容。

---

### 规则 5：STRINGTABLE

```regex
^\s*(IDS_[A-Z0-9_]+)\s+"([^"]*)"
```

用途：

* 提取字符串表中的资源字符串。
* 大多数属于待汉化内容。
* 需要记录资源 ID 与字符串的对应关系。

---

### 规则 6：版本信息字段

```regex
^\s*VALUE\s+"([^"]+)"\s*,\s+"([^"]*)"
```

用途：

* 提取 VERSIONINFO 中的字段。
* 需要根据字段名判断是否汉化。

建议：

| 字段               | 处理建议                   |
| ---------------- | ---------------------- |
| FileDescription  | 可汉化或待复核                |
| ProductName      | 通常保留 `System Informer` |
| CompanyName      | 不汉化                    |
| LegalCopyright   | 不汉化                    |
| OriginalFilename | 不汉化                    |

## 十三、排除规则示例

### 排除规则 1：资源 ID

```regex
\b(?:IDS|IDC|IDD|IDM|IDI|IDB|IDR)_[A-Z0-9_]+\b
```

排除原因：

资源标识符，不属于用户可见文本。

---

### 排除规则 2：Windows 类名

```regex
\b(?:SysListView32|SysTreeView32|Button|Static|Edit|ComboBox|msctls_progress32)\b
```

排除原因：

Win32 控件类名，不应汉化。

---

### 排除规则 3：DLL / EXE / SYS 文件名

```regex
\b[A-Za-z0-9_.-]+\.(?:dll|exe|sys|mui|pdb|lib)\b
```

排除原因：

文件名或模块名，不应汉化。

---

### 排除规则 4：注册表路径

```regex
(?:HKEY_|HKCU|HKLM|Software\\|System\\CurrentControlSet\\|Microsoft\\Windows)
```

排除原因：

注册表路径或注册表项，不应汉化。

---

### 排除规则 5：NT 对象路径

```regex
^\\\\(?:Device|Driver|FileSystem|BaseNamedObjects|KnownDlls|Sessions)\\
```

排除原因：

Windows NT 对象路径，不应汉化。

---

### 排除规则 6：命令行参数

```regex
^[-/][A-Za-z0-9_-]+$
```

排除原因：

命令行参数，不应汉化。

---

### 排除规则 7：纯格式化占位符

```regex
^%[-+#0-9.*hlIwsztdj]*[diuoxXfFeEgGaAcCsSpn]$
```

排除原因：

纯格式化占位符，不属于自然语言文本。

## 十四、特殊汉化规则

### 1. 保留格式化占位符

示例：

```c
L"Unable to open process %lu."
```

可以汉化为：

```text
无法打开进程 %lu。
```

要求：

* `%lu` 必须保留。
* `%s`、`%d`、`%Ix`、`%p` 等占位符数量和顺序必须一致。
* 如果调整语序，需要支持带位置的格式化方式时才允许改变顺序。

---

### 2. 保留转义字符

示例：

```c
L"Line 1\r\nLine 2"
```

要求：

* `\r\n`、`\n`、`\t` 必须保留语义。
* 不允许破坏字符串转义。

---

### 3. 保留 Windows 助记键

示例：

```rc
MENUITEM "&File", IDM_FILE
```

汉化时可以变为：

```text
文件(&F)
```

要求：

* 记录原始助记键。
* 支持检查同一菜单层级下助记键是否冲突。
* 支持人工复核助记键。

---

### 4. 产品名默认不翻译

以下内容默认保留：

```text
System Informer
Process Hacker
Windows
Microsoft
NT
Win32
```

但如果出现在完整说明句中，只翻译句子中的普通文本，产品名保留。

---

### 5. 插件资源需要单独统计

System Informer 插件也可能包含独立菜单、对话框和字符串。

分析时需要记录字符串来源：

```text
主程序
插件
工具
公共库
第三方代码
未知
```

插件字符串不能因为不在主程序目录中而忽略。

---

## 十五、字符串记录字段说明

每一条被扫描到的字符串，都需要保存为一条记录。

记录重点不是用代码结构描述，而是让后续页面能够清楚展示：

```text
这个字符串来自哪里
为什么需要汉化或排除
命中了哪条规则
当前处理状态是什么
```

### 字符串记录需要包含以下信息

| 字段         | 说明                                                      |
| ---------- | ------------------------------------------------------- |

## 十九、推荐分析流程

### 1. 扫描文件

扫描 System Informer 项目中的目标文件，重点扫描：

```text
.rc
.rc2
.c
.h
```

优先级建议：

```text
资源文件 > C 源码文件 > 头文件 > 其他配置文件
```

---

### 2. 提取字符串

根据不同文件类型提取字符串。

资源文件中重点提取：

```text
CAPTION
MENUITEM
POPUP
LTEXT
CTEXT
RTEXT
PUSHBUTTON
DEFPUSHBUTTON
CHECKBOX
RADIOBUTTON
GROUPBOX
STRINGTABLE
VERSIONINFO
```

C / H 文件中重点提取：

```text
"xxx"
L"xxx"
TEXT("xxx")
_T("xxx")
MessageBox(...)
TaskDialog(...)
SetWindowText(...)
```

---

### 3. 判断是否需要汉化

判断顺序建议为：

```text
先判断是否明确排除
再判断是否明确待汉化
最后处理待复核
```

也就是：

```text
排除规则 > 待汉化规则 > 上下文分析 > 待复核
```

---

### 4. 建立对应关系

每个字符串都需要关联到一种结果：

```text
待汉化规则
排除规则
待复核
```

不能出现没有状态、没有原因、没有对应规则的字符串。

---

### 5. 人工复核

对自动判断不明确的字符串进入待复核，例如：

```text
System Informer
Process Hacker
服务名
驱动名
日志文本
包含格式化占位符的字符串
既可能是显示名又可能是内部标识的字符串
```

---

### 6. 规则优化

人工复核完成后，需要把结果沉淀为规则：

```text
确认为待汉化 → 新增或优化待汉化规则
确认为排除 → 新增或优化排除规则
发现误匹配 → 收窄原有规则
```

---

### 7. 重新匹配

规则调整后，需要支持重新匹配项目字符串，更新：

```text
字符串状态
规则命中数量
文件覆盖率
整体覆盖率
```

## 二十、Python 脚本负责的工作

Python 脚本不是主要分析工具，不负责复杂的源码语义判断。

### 1. 导出待翻译文件

Python 提取脚本根据 Codex 已经确认的分析结果，生成翻译工作文件。

输入：

```text

review_required.json
excluded.json
analysis_report.json

status 为 未翻译
保留原文、文件路径、行号、上下文、规则来源

[
  {
    "id": "SI-RC-000001",
    "source": "Properties",

    "rule": "RC 菜单项文本",
    "status": "未翻译",
    "note": ""
  }
]
```

## 二十一、人工翻译流程

人工只需要处理：

```text
localization/output/untranslated.json
```

人工填写：

```json
"translation": ""
```

填写完成后，记录转入：

```text
localization/output/translated.json
```

人工翻译时需要注意：

```text
不要删除格式化占位符
不要破坏转义字符
不要随意删除菜单助记键
产品名 System Informer 默认保留
资源 ID、路径、DLL 名称不翻译
不确定的内容标记备注或转入待复核
```

## 二十二、Python 回写脚本负责的工作

Python 回写脚本用于读取已翻译文件，并将译文应用到 System Informer 源码中。

输入：

```text
localization/output/translated.json
System Informer 原始源码
```

输出：

```text
汉化后的源码目录
应用报告
```

示例路径：

```text
systeminformer_zh/
localization/output/apply_report.json
```

---

### 回写脚本处理流程

```text
读取 translated.json
  ↓
校验译文
  ↓
定位源码文件
  ↓
根据字符串 ID、文件路径、行号、上下文匹配原文
  ↓
替换为中文译文
  ↓
保留源码格式
  ↓
输出修改后的源码
  ↓
生成应用报告
```

---

### 回写时必须保留

```text
原始引号
L 宽字符串前缀
TEXT() / _T() 宏
RC 文件语法
资源 ID
缩进
换行
逗号
注释
格式化占位符
转义字符
菜单助记键
```

示例：

```rc
MENUITEM "Properties", IDM_PROPERTIES
```

回写后：

```rc
MENUITEM "属性", IDM_PROPERTIES
```

示例：

```c
L"Unable to open process %lu."
```

回写后：

```c
L"无法打开进程 %lu。"
```

## 二十三、翻译文件状态流转

每条字符串的状态流转如下：

```text
Codex 确认为待汉化
  ↓
Python 导出到 untranslated.json
  ↓
人工填写 translation
  ↓
进入 translated.json
  ↓
Python 校验
  ↓
Python 回写源码
  ↓
应用成功 / 应用失败
```

待复核流程：

```text
Codex 无法明确判断
  ↓

  ↓
人工确认
  ↓

```

排除流程：

```text
Codex 确认为不需要汉化
  ↓
进入 excluded.json
  ↓
不参与翻译和回写
```

## 二十六、覆盖率统计

需要统计以下指标：

```text
总字符串数
待汉化字符串数
排除字符串数
待复核字符串数
已确认字符串数
未覆盖字符串数
待汉化规则覆盖数
排除规则覆盖数
总覆盖率
```

还需要按文件类型统计：

```text
.rc 文件字符串覆盖率
.c 文件字符串覆盖率
.h 文件字符串覆盖率
插件字符串覆盖率
主程序字符串覆盖率
```

覆盖率公式：

```text
总覆盖率 = (待汉化规则覆盖数 + 排除规则覆盖数) / 总字符串数
```

目标：

```text
待汉化规则 + 排除规则 + 人工复核结果 覆盖所有识别到的字符串
```

## 二十七、翻译校验要求

在应用翻译前，需要执行校验。

### 1. 占位符校验

检查原文和译文中的格式化占位符是否一致。

例如：

```text
原文：Unable to open process %lu.
译文：无法打开进程 %lu。
结果：通过
```

如果译文丢失 `%lu`，则校验失败。

常见占位符包括：

```text
%s
%d
%u
%lu
%llu
%Ix
%p
%ws
```

检查项：

* 占位符数量一致。
* 占位符类型一致。
* 转义百分号 `%%` 不应被误判。
* 翻译后不能丢失参数。

---

### 2. 转义字符校验

检查以下内容是否被错误删除或修改：

```text
\n
\r\n
\t
\\
\"
```

---

### 3. 空译文校验

`translation` 为空时不能回写源码。

---

### 4. 原文匹配校验

回写前必须确认源码中仍然能找到对应原文。

如果文件内容已经变化，导致无法匹配，需要标记为应用失败，不能盲目替换。

---

### 5. 重复原文校验

如果同一个文件中存在多个相同英文字符串，不能只靠原文替换。

需要结合：

```text
字符串 ID
文件路径
行号
上下文源码
规则类型
资源 ID
```

尽量精确定位。

---

## 二十八、源码回写要求

应用翻译时必须满足以下要求。

### 1. 不破坏源码结构

需要保留：

```text
引号类型
L 前缀
TEXT() / _T() 宏
RC 文件语法
资源 ID
缩进
换行
逗号
注释
```

示例：

```rc
MENUITEM "Properties", IDM_PROPERTIES
```

应变为：

```rc
MENUITEM "属性", IDM_PROPERTIES
```

---

### 2. 保留宽字符串前缀

示例：

```c
L"Properties"
```

应变为：

```c
L"属性"
```

不能变成：

```c
"属性"
```

---

### 3. 保留 TEXT / _T 宏

示例：

```c
TEXT("Properties")
```

应变为：

```c
TEXT("属性")
```

---

### 4. 保留格式化占位符

示例：

```c
L"Unable to open process %lu."
```

应变为：

```c
L"无法打开进程 %lu。"
```

其中 `%lu` 必须保留。

---

### 5. 保留转义字符

示例：

```c
L"Line 1\r\nLine 2"
```

翻译后仍然需要保留正确的 `\r\n`。

---

### 6. 保留菜单助记符

示例：

```rc
MENUITEM "&File", IDM_FILE
```

可以翻译为：

```rc
MENUITEM "文件(&F)", IDM_FILE
```

不能直接丢失助记键，除非人工明确确认。

## 三十一、最终验收标准

### 1. Codex 分析验收

1. Codex 能够逐个文件分析 System Informer 源码。
2. Codex 能够识别 `.rc`、`.rc2`、`.c`、`.h` 中的字符串。
3. Codex 能够判断字符串是否待汉化、排除或待复核。
4. Codex 能够为每条待汉化内容关联提取规则。
5. Codex 能够为每条排除内容关联排除规则。
6. Codex 能够输出字符串分析记录。
7. Codex 能够输出文件分析进度。
8. 每条字符串都必须具备状态、原因和对应关系。
9. 每条待汉化内容都能被待汉化规则覆盖。
10. 每条排除内容都能被排除规则覆盖。

---

### 2. Python 导出验收

1. Python 能够根据 Codex 分析结果生成未翻译文件。
2. 未翻译文件只包含 Codex 确认需要汉化但尚未翻译的内容。
3. Python 能够生成待复核文件。
4. Python 能够生成排除文件。
5. Python 能够生成分析报告。
6. Python 不重新判断字符串是否需要汉化，只按 Codex 结果执行导出。

---

### 3. 人工翻译验收

1. 人工只需要处理 `untranslated.json`。
2. 已翻译内容需要进入 `translated.json`。
3. 已翻译文件只包含人工已经填写译文的内容。
4. 不确定内容应进入待复核流程。
5. 翻译过程中不能丢失占位符、转义字符和必要助记键。

---

### 4. Python 回写验收

1. Python 能够读取已翻译文件并回写源码。
2. Python 回写时不能破坏 `.rc`、`.c`、`.h` 文件语法。
3. Python 回写时必须保留 `L` 前缀。
4. Python 回写时必须保留 `TEXT()` / `_T()` 宏。
5. Python 回写时必须保留资源 ID。
6. Python 回写时必须保留格式化占位符。
7. Python 回写时必须保留转义字符。
8. Python 回写时必须保留菜单助记键。
9. Python 无法准确匹配源码位置时，必须跳过并记录失败原因。
10. Python 必须生成 `apply_report.json`。
